# DeepSeek Harness 移动端（配套 App）设计

手机是随身的控制台和查看器，电脑是真正干活的地方。两端同属一个产品：同一套主题变量、
同一套气质，为手机重新编排，不做网页缩小版。

---

## 1. 架构：桥接插件，不是第二个服务

```
┌───────────────────────────────────────────────────────────────┐
│ 手机端 PWA（同一套 --dsw-* 主题变量，移动优先重排）             │
│   打开即用 · 添加到主屏 · 推送通知                              │
└──────────────────────────┬────────────────────────────────────┘
                           │ HTTPS + WSS（真实证书，来自 Cloudflare Tunnel）
                           │ 隧道只放行 /mobile/*，其余路径不暴露
┌──────────────────────────▼────────────────────────────────────┐
│ 电脑端引擎（127.0.0.1:<固定端口>）                              │
│   ┌─────────────────────────────────────────────────────────┐ │
│   │ dsh-mobile-bridge（本设计新增的内置插件）                 │ │
│   │  · 配对码 / 设备令牌 / 权限 / 撤销                        │ │
│   │  · 会话：列出·搜索·新建·发消息·停止·重生成                │ │
│   │  · 模型：读写引擎的模型配置与凭据，带 revision 冲突检测    │ │
│   │  · 事件流：流式输出、回合状态、完成/失败                  │ │
│   └─────────────────────────────────────────────────────────┘ │
│        ▲ 进程内直接调用（无协议逆向）                            │
│   会话服务 · settings 命名空间 llm-pi-ai · 凭据域 · web seam     │
└───────────────────────────────────────────────────────────────┘
```

**为什么做成引擎内的插件，而不是电脑端另起一个服务**：会话、模型配置、凭据三者都是引擎
的进程内服务；插件直接拿到它们，不需要逆向任何私有协议，也不会因为引擎升级而失效。引擎的
HTTP/WS 服务已经能注册路由和升级连接，桥接只需要在其上加一层「谁的手机、能做什么」。

**为什么还需要 Cloudflare Tunnel**：引擎明确拒绝绑定 `0.0.0.0`（会把远程代码执行暴露到
局域网）。隧道把「本机 127.0.0.1」安全地变成「手机可访问的 HTTPS」，且本机已有 cloudflared
在跑。局域网直连作为可选（同一 Wi-Fi 时延迟更低），跨网络一律走隧道。

## 2. 协议：JSON over HTTPS + 一条 WSS

- 一元请求走 HTTPS，路径全部挂在 `/mobile/` 下；事件走 WebSocket。
- 信封：`{ "v": 1, "type": "...", "id": "...", ... }`；错误统一
  `{ ok: false, code, message, detail? }`，`code` 是可判定的机器码（`E_REVISION`、
  `E_UNAUTHORIZED`、`E_RATE_LIMITED`、`E_BUSY`…），`message` 是给用户看的中文。
- 事件带 `seq`（每设备单调递增）。断线重连时带 `Last-Event-Seq`：
  仍在缓冲区内 → 增量回放；超出 → 服务端回 `E_RESYNC`，客户端重新拉一次 state。
  这就是「断线可恢复」的实现方式，不需要客户端理解协议细节。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/mobile/pair` | 用配对码换设备令牌（首次绑定） |
| GET | `/mobile/state` | 引导：设备、会话摘要、模型文档版本、能力开关 |
| GET | `/mobile/sessions?query=&cursor=` | 会话列表 + 全文搜索（引擎已有查询索引） |
| POST | `/mobile/sessions` | 新建会话（可带模型） |
| GET | `/mobile/sessions/:id/messages` | 历史消息（游标分页） |
| POST | `/mobile/sessions/:id/messages` | 发消息 / 继续对话 → 返回 turnId |
| POST | `/mobile/turns/:id/cancel` | 停止生成 / 取消任务 |
| POST | `/mobile/turns/:id/regenerate` | 重新生成 |
| PATCH | `/mobile/sessions/:id` | 切换该会话使用的模型 |
| GET | `/mobile/models` | 模型配置文档（含 `revision`） |
| PUT | `/mobile/models` | 提交变更 `{ baseRevision, ops[] }` |
| GET/POST/DELETE | `/mobile/devices` | 绑定关系：查看 / 解除 |
| WS | `/mobile/events` | 流式输出、回合状态、完成与失败 |

## 3. 绑定与安全

**首次配对（简单优先）**
1. 电脑端「移动端」页显示二维码，内容是 `https://<域名>/mobile/pair?code=XXXX-XXXX`；
   手机扫码即完成，**不需要理解任何协议**。
2. 兜底：手输 6 位配对码（同一个人在两台设备之间搬一次数字）。
3. 配对码 5 分钟过期、一次性、连续 5 次失败锁定 1 分钟；换码即作废旧码。

**令牌**
- 配对成功后电脑端生成 32 字节随机令牌，**只存哈希**；手机端存 IndexedDB（不用
  localStorage）。
- 令牌长期有效，可随时在任一端撤销（手机端「我的设备」、电脑端「移动端」页都能看到
  全部绑定、最后活跃时间、权限）。
- 权限最小化：默认只允许「读会话 + 发消息 + 停止」；**改模型配置需要单独勾选**，
  删设备需要重新确认。

**传输与敏感字段**
- HTTPS（隧道提供真实证书）+ WSS，手机端不出现证书警告，也不依赖局域网可信。
- API Key：只写不读。写入后任何读取接口只回 `apiKeyConfigured: true/false`，
  回显一律打码；事件流、日志、错误详情里都不含 key。手机端只在提交瞬间持有明文，
  不落盘、不进历史。
- 桥接只监听本机；隧道只转发 `/mobile/*`，引擎原有界面与接口不对外暴露。

## 4. 模型配置的双向同步（重点）

**共享模型**
```
ModelDoc {
  revision: number        # 电脑端每次成功写入 +1（source of truth）
  updatedAt: string
  items: ModelItem[]
}
ModelItem {
  id            # 稳定标识（手机端新建时由电脑端分配）
  name          # 显示名
  provider      # 供应方
  baseURL       # API 地址
  apiMode       # openai-completions / openai-responses / codex_responses …
  modelId       # 模型 ID
  params        # 参数（温度、上下文、输出上限…）
  enabled       # 启用状态
  tags[]        # 标签
  order         # 排序
  apiKeyRef     # 凭据引用名（不含值）
  apiKeyConfigured  # 只读：是否已配置
}
```
字段以**你电脑端 harness 的真实配置结构**为准（`llm-pi-ai` 命名空间 + 凭据域），
不额外发明一套；手机端只是同一份文档的副本 + 可写入口。

**写路径**：手机端提交 `{ baseRevision, ops[] }`。
- `baseRevision === 当前` → 应用，`revision++`，事件推给所有在线设备。
- 不一致 → **409 `E_REVISION`**，附带服务器当前文档 + 字段级 diff。绝不静默覆盖。

**冲突策略（三层，从自动到手动）**
1. **不同字段**：自动合并（你改 `order`、电脑端改 `params` → 两者都保留）。
2. **同一字段**：标为冲突并停住，手机端列出「你的值 / 电脑端的值 / 时间 / 来源」，
   由人选择保留哪一个；选择结果写回，`revision++`。
3. **删除 vs 编辑**：以删除为准但提示「这项已被删除」，避免复活已删除的配置。
4. **API Key 冲突**：值不回显，只能选「用手机刚填的」或「保留电脑端的」，界面只显示
   `••••最近更新时间`。

**电脑端改动回流**：电脑端本地改配置 → `revision++` → 手机端下次拉取或提交时拿到新
文档并自动刷新界面；若手机端有未提交草稿，则进入上面的冲突流程。

## 5. 通知

- **在线**：WS 事件直接驱动应用内提示（回合完成 / 失败 / 需要授权 / 令牌失效），
  带角标，点通知直接跳到对应会话。
- **后台**：Web Push（VAPID，电脑端生成并保管密钥对，订阅存桥接内）。
  Android Chrome 直接可用；iPhone 需要先「添加到主屏幕」（iOS 16.4+ 支持）。
- **诚实边界**：电脑端没在跑就没有任何通知 —— 干活的机器不在线，本来也没有可通知的事。
  电脑端页面会显示「当前 N 台设备已绑定、推送 N 条订阅」。

## 6. 视觉与交互：同气质，移动重排

**同一套设计语言（不靠模仿，靠同一份变量）**
从引擎的 `dsh-client-ui-theme` 抽出 `--dsw-static-*` 调色板与 `--dsw-alias-*`
语义映射（浅色/深色两套），构建时生成手机端 `theme.css`；引擎升级后重新跑一次抽取脚本，
两端永远同色。字体层级、圆角、间距、边框、代码块背景全部走 alias 变量，不写死色值。

**为手机重新编排（不是网页缩小）**
| 电脑端 | 手机端 |
| --- | --- |
| 左侧会话侧栏 + 右侧栏 | 会话列表独立成页：搜索置顶、下拉刷新、长按重命名/删除 |
| 多栏并排 | 单列对话流 + 底部输入框（安全区适配、字号跟随系统） |
| 顶部工具条 | 会话头部：标题 + 状态点 + 「⋯」动作表（停止/重生成/切模型） |
| 模型下拉在卡片里 | 底部动作抽屉（半屏），触达区 ≥44pt |
| 设置=多分组页面 | 分组列表页：移动端 / 模型 / 通知 / 关于 |
| 代码块原样 | 横向滚动 + 复制按钮 + 等宽字体 |

**状态可见**：连接状态、正在生成的回合、队列中的任务、失败原因都在对话头部一行内
说清；断线时输入框不消失，改为「重连中…」并保留草稿。

## 7. 路线图

- **v0（本次）**：配对与设备管理、会话列表与搜索、对话与流式输出、停止/重生成、新建会话、
  模型切换、桥接与 PWA 跑通、主题抽取。
- **v1**：模型增删改 + 冲突选择界面、API Key 写入、模型连通性测试。
- **v2**：Web Push 通知、二维码配对、cloudflared 固定域名、局域网直连。
- **v3**：离线缓存与草稿、附件上传（图片走已有视觉链路）、多电脑切换。
